# VLA Development Guide: Files, Workflows, and Updates

## Question 1: Which File to Run for End-to-End VLA?

### Quick Answer
```bash
cd vla
python3 vla_standalone.py
```

### Three VLA Scripts - When to Use Each

| Script | When to Use | Time | Notes |
|--------|------------|------|-------|
| **vla_standalone.py** | Regular inference & benchmarking | ~6.16s | **USE THIS** - Calls pre-built C++ binaries |
| vla.py | Understanding Python structure / research | ~23s | Slow (includes df.build() every run) |
| vla_cpp.py | Never run directly | — | Helper module, imported by vla_standalone.py |

## Question 2: Update & Test Workflow

### The Three Types of Files in the Repo

```
VLA Repo Structure
├── Files YOU write (source code)
│   ├── cc/bf16/my_kernel.cc          ← User writes kernel implementation
│   ├── kernel_testing/my_kernel/test_my_kernel.py  ← User writes test
│   └── vla/my_vla_component.py       ← User writes VLA layer
│
├── Files GENERATED by Allo (compilation artifacts)
│   ├── kernel_testing/my_kernel/top.prj/
│   │   ├── CMakeLists.txt             ← Allo generates
│   │   ├── top.mlir                   ← Allo generates
│   │   ├── build/final.xclbin         ← Allo generates
│   │   └── build/insts.txt            ← Allo generates
│   └── vla/my_component/unified.prj/  ← Allo generates
│       └── build/
│           ├── final.xclbin
│           └── insts.txt
│
└── Compiled executables
    └── vla/vision_block/unified.prj/build/vision_encoder  ← Allo generates
```

### Update Workflow: Step-by-Step

#### **Scenario: Update a kernel** (e.g., GELU optimization)

**Step 1: Modify the kernel source**
```bash
# Edit the C++ source
vim cc/bf16/gelu_bf16.cc

# NO CHANGES to vla_standalone.py needed if kernel interface stays same
```

**Step 2: Rebuild the kernel with Allo**
```bash
# If there's a build script (user-written):
cd kernel_testing/gelu
python build_gelu.py  # Generates .prj/build/final.xclbin

# OR manually with Allo:
cd kernel_testing/gelu
python3 << 'ALLO'
import allo
from allo.ir.types import bfloat16 as bf16

# ... define kernel ...
sch = s.build()
sch.save_graph("top.prj", top_module=s)
ALLO
```

**Step 3: Test the updated kernel**
```bash
cd kernel_testing/gelu
python test_gelu_bf16_new.py  # Should PASS if kernel is correct
```

**Step 4: Regenerate VLA component if needed**
If the kernel affects a full component (vision encoder, text encoder):
```bash
cd vla/vision_block
python build_vision_encoder.py  # Rebuilds unified.prj/build/vision_encoder binary

# Then test:
cd ..
python3 vla_standalone.py  # Runs with new kernel
```

**Step 5: Commit changes**
```bash
git add cc/bf16/gelu_bf16.cc kernel_testing/gelu/test_gelu_bf16_new.py
git commit -m "Optimize GELU kernel: improve vectorization"

# .prj/build/ is .gitignored, don't commit compiled artifacts
```

---

#### **Scenario: Update vla.py or component Python logic**

**Step 1: Modify Python code**
```bash
vim vla/text_encoder_bf16.py
```

**Step 2: Test the change**
```bash
cd vla
python3 text_encoder_bf16.py  # Test that component
python3 vla_standalone.py      # Test end-to-end
```

**Step 3: Commit**
```bash
git add vla/text_encoder_bf16.py
git commit -m "Update text encoder RoPE logic"
```

### What Gets .gitignore'd (Don't Commit)

```
*.prj/build/              ← Compiled binaries (rebuild on every machine)
*.xclbin                  ← Allo-generated
insts.txt                 ← Allo-generated
*.mlir                    ← Allo-generated intermediate
test_results*.log         ← Test output
```

These are **rebuilt** when the kernel source changes, so don't check them in.

---

### What Should Be Committed

```
cc/bf16/my_kernel.cc              ← Kernel source (user-written)
kernel_testing/my_kernel/test_*.py ← Test code (user-written)
vla/*.py                           ← Model code (user-written)
README.md                          ← Documentation
```

These are the **source of truth**. Allo artifacts are derived from these.

## Summary: The Full Workflow

```
1. User writes kernel source code
   └─> cc/bf16/my_kernel.cc

2. User writes build script OR runs Allo manually
   └─> Allo generates .prj/ directory with top.mlir, CMakeLists.txt
   └─> Allo runs cmake + make
   └─> Generates .prj/build/final.xclbin + insts.txt

3. User writes test script
   └─> kernel_testing/my_kernel/test_my_kernel.py

4. User runs test
   └─> Test loads .prj/build/final.xclbin
   └─> Compares output vs PyTorch
   └─> PASS/FAIL

5. If full component affected (vision/text/action):
   └─> User regenerates unified component binary
   └─> vla/vision_block/unified.prj/build/vision_encoder

6. User runs vla_standalone.py
   └─> Loads all pre-built binaries
   └─> Reports end-to-end timing

7. User commits only source files
   └─> git add cc/bf16/*.cc kernel_testing/*/*.py vla/*.py
   └─> .prj/build/ is auto-ignored
```

## Key Takeaways

| Topic | Answer |
|-------|--------|
| **Run for end-to-end?** | `vla_standalone.py` |
| **Files generated by Allo?** | `.prj/build/final.xclbin`, `insts.txt`, `top.mlir`, `CMakeLists.txt` |
| **Files you write?** | Kernel source (`.cc`), test scripts (`.py`), model code (`.py`) |
| **What to commit?** | Only source files (`.cc`, `.py`); .gitignore build artifacts |
| **Update kernel?** | Edit `.cc` → rebuild with Allo → test → commit source |
| **Update Python?** | Edit `.py` → test → commit |
