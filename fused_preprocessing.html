Fused Preprocessing: Conv2d Patch Embedding on AMD NPU

Overview

The fused preprocessing pipeline implements Conv2d patch embedding entirely on the AMD XDNA NPU — converting a raw image into patch embeddings fed into a Vision Transformer (ViT).

Goal: Transform image [C=3, 512, 512] → patch embeddings [1024, 768]

Mathematically equivalent to torch.nn.Conv2d(3, 768, kernel_size=16, stride=16), but decomposed into two NPU kernels: im2col and GEMM.

Mathematical Background

A 512×512 image with patch size 16×16 produces a 32×32 = 1024 patch grid. Each patch has C × KH × KW = 3 × 16 × 16 = 768 elements. 

output[seq, embd]  =  Σ_{c,ky,kx}  image[c, ph·16+ky, pw·16+kx]  ×  kernel[embd, c, ky, kx]

where  seq = ph · PW + pw   (flattened patch index)

Decomposing into im2col + GEMM:

patches[seq, k]      =  image[c, ph·16+ky, pw·16+kx]     where k = c·KH·KW + ky·KW + kx
output[seq, embd]    =  patches[seq, :] @ kernel_B[:, embd]

NPU Kernel 1: im2col

Purpose

Rearranges image pixels from strip layout into patch-column layout — each output row is one flattened patch vector of length 768, ready for matrix multiplication.

Dimensions

SymbolValueMeaning
IMG2D48C × KH — flattened channel×row
PIX_QT128Pixel columns per quarter-row call
PW_QT8Patches per quarter-row call
K_FULL768C × KH × KW — full patch length

Call Pattern & SRAM Budget

128 total calls = PH (32 strip rows) × 4 (quarter-row divisions)

Input  [48, 128] = 12,288 B × 2 (double-buffer) = 24,576 B
Output [8, 768]  = 12,288 B × 2 (double-buffer) = 24,576 B
Total: 49,152 B + ~1 KB stack < 65,536 B ✓

Index Mapping

pat[pw,  c·KH·KW + ky·KW + kx]  =  img[c·KH + ky,  pw·KW + kx]

for pw ∈ [0, 8)
  for c  ∈ [0, 3)
    for ky ∈ [0, 16)
      for kx ∈ [0, 16)   ← mapped to one 16-wide AIE vector op

Vectorization: The inner kx dimension (size 16) maps exactly to one 16-element bfloat16 vector load/store. Total vector ops per call: PW_QT × CHANNELS × KH = 8 × 3 × 16 = 384. No scalar fallback, no masking.

NPU Kernel 2: GEMM

Purpose

Multiplies the patch matrix against the pre-transposed conv kernel to produce patch embeddings: 

patches[32, 768]  @  kernel_B[768, 128]  →  output[32, 128]

Core Configuration

ParameterValueMeaning
Pm1M-parallel tiles (no M sharding)
Pn4N-parallel lanes
Pk4K-reduction chain depth
M_TILE32Rows per GEMM call (one patch row)
N_TILE128Output dims per call (4 × 32)
K_FULL768Full K dimension
16 total cores: Pm × Pn × Pk = 1 × 4 × 4 (exactly the NPU physical limit)

A [32, 192] × 2 (double-buf) = 24,576 B
B [192, 32] × 2 (double-buf) = 24,576 B
C [32,  32] × 4 (pipe depth) =  8,192 B
Total: ~57 KB < 64 KB ✓

Call Pattern

192 total calls = n_m × n_n = 32 × 6
n_m = SEQ / M_TILE = 1024 / 32 = 32
n_n = EMBD_DIM / N_TILE = 768 / 128 = 6

16-Core Grid Diagram

Each row is a Pn lane (handles a 32-column slice of C). Each column is a Pk stage (handles a 192-element K-slice of A and B). Stream pipes flow left → right, accumulating partial sums.

K-Chain Accumulation (per core)

pk=0:  partial = A[:,   0..191] @ B[  0..191, :]    (bf16 matmul → cast f32)
       pipe.put(partial)

pk=1:  partial = A[:, 192..383] @ B[192..383, :]
       acc = partial_f32 + pipe.get()
       pipe.put(acc)

pk=2:  partial = A[:, 384..575] @ B[384..575, :]
       acc = partial_f32 + pipe.get()
       pipe.put(acc)

pk=3:  partial = A[:, 576..767] @ B[576..767, :]
       acc = partial_f32 + pipe.get()    ← sum of all 4 K-slices
       C_local[:] = acc                  ← write output tile
Type handling: matmul runs in bfloat16 for hardware throughput; inter-stage accumulation uses float32 to avoid precision loss across 4 partial sums. The implicit cast (matmul_f32[:,:] = matmul_result[:,:]) works around allo's type inference limitation with mixed-type allo.add.

Static Weight Preparation

Kernel weights are pre-tiled once at model load time so each tile is contiguous — no per-call CPU gather.

kernel [768, 3, 16, 16]
  reshape → [768, 768]          = [N, K]
  for n in range(6):
    kernel_B_tiles[n] = kernel_2d[n*128:(n+1)*128, :].T   shape [768, 128]

Result: kernel_B_tiles [6, 768, 128]  — each tile contiguous in memory

im2col Kernel — Slide Diagram

im2col: Image-to-Column Patch Extraction

▷ Rearranges image pixels into patch-row layout

  • – Input: strip slice [48 × 128] (C·KH rows × 128 pixel-cols)
  • – Output: 8 flattened patches [8 × 768]
  • – 128 total calls (32 strip-rows × 4 quarter-row divisions)

▷ Scalar → Vector: inner kx loop (size 16)

  • – Maps exactly to one 16-element bf16 aie::load_v<16>
  • – No scalar fallback, no masking needed
  • – vec_factor = 16 (constrained by KW = 16)

▷ Index mapping per vector op:

pat[pw, c·256 + ky·16 + kx]
  ← img[c·16 + ky, pw·16 + kx]

for pw ∈ [0,8), c ∈ [0,3), ky ∈ [0,16)
  kx: one 16-wide AIE vector load/store

▷ SRAM Budget (64 KB local memory)

  • – In  [48,128] × 2 (dbl-buf) = 24,576 B
  • – Out [8,768]  × 2 (dbl-buf) = 24,576 B
  • – Total 49 KB < 64 KB ✓

384 vector ops per call  ·  0 MACs  ·  pure data reorganisation
